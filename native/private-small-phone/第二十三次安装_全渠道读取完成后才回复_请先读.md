# 第二十三次安装：全渠道读取完成后才回复

本包版本为网页核心 v898／原生 1.0.23 (23)。请把整个 `SmallPhone_v898_AllChannelInspectionGate` 目录复制到 Mac，直接打开其中的 `PhoneCompanionTest.xcodeproj`。不要逐个文件覆盖旧工程，也不要从旧目录继续编译。

## 这次真正修复的原因

v897 的拦截只保护同一条已识别的用户消息。“查一次所有的”没有被解析成“全部数据”，早期读取门禁因此退出，普通模型先开始回复；后面的事实守卫又识别到数据话题并启动真实读取，于是出现读取尚未结束先说一轮、读取完成再说一轮。

v898 不再依赖单一提示词补丁。聊天、电话和共同生活共用全局读取状态与生成代次：

- 真实读取一排队，立即冻结三个场景的普通模型输出。
- 读取开始前已经在生成的回复会变成旧代次；即使已经生成完，也不能再显示或播放。
- 所有读取项目进入成功、不可用或超时终态后，才把成功事实交给模型。
- 只有这次“读取完成回复”可以越过读取锁，并且只自然回复一次。
- 系统逐项清单、未授权、超时和技术错误只留在内部，不会冒充角色消息。

## Mac 安装

1. 解压本包，把完整的 `SmallPhone_v898_AllChannelInspectionGate` 文件夹复制到 Mac。
2. 打开其中唯一的 `PhoneCompanionTest.xcodeproj`。
3. 在 Xcode 执行 `Product → Clean Build Folder`。
4. 选择 `PhoneCompanionTest` Scheme 和真实 iPhone，点击运行。
5. 不要单独运行 Report、Monitor、Shield 或通知扩展 Target。

## 这次必须做的真机验收

分别在微信聊天、电话和共同生活测试“查一次所有的”或“再刷一遍全部数据”：

- 顶部横幅应逐项显示正在读取的内容。
- 横幅仍在进行时，角色不得发文字、说话或显示旧模型回复。
- 全部结束后，只允许一轮符合角色口吻的自然回复。
- 不应出现逐项系统播报、权限诊断、超时提示或第二轮重复回复。
