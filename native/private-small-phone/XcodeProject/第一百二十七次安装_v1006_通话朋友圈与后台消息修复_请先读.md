# 第一百二十七次安装：v1006 通话、朋友圈与后台消息修复

当前版本：网页 v1006；私人 iOS 1.0.127 (127)；原生桥 25。

## 已查明的真实原因

1. v996 切换到新的独立伴生云后，只配置了 APNs 和系统密钥，没有任何模型提供方。后台任务因此在生成阶段返回 `no-provider`，没有进入 APNs。
2. 旧“当前模型”提示没有同步私人 App 当前角色实际使用的 API 地址、Key 和模型名，只证明任务入库。
3. 私人版隔离包装丢掉 `roleBackgroundDispatchNow(true)` 的 `keepalive` 参数；App 退到后台后，加速派发请求可能被 iOS 取消。
4. 旧测试没有核对服务器生成、outbox 和 APNs 最终状态，入队成功会被误解为即将送达。

## 本次修改

1. 开启后台主动联系时，把当前角色实际使用的 HTTPS API 线路加密同步到独立私人云；服务器优先执行该线路。关闭功能时清除模型线路。
2. “立即模拟后台主动消息”保留任务编号，返回 App 后继续核对模型生成与 APNs 结果；失败显示真实阶段和原因，不生成本地假消息。
3. 后台派发包装完整转发 `keepalive` 等参数；`phone-role-push` 新函数已部署到独立云。
4. 电话只携带相关长期记忆和有上限的近期历史，减少巨大请求造成的长时间无字幕、无声音或超时。
5. 朋友圈评论保存准确角色与原评论目标，限制评论线程和聊天上下文；只请求一次真实模型，失败只保留重试入口，绝不伪造角色回复。

## Mac 安装与真机验证

1. 完整解压 ZIP，不覆盖任何旧工程。
2. 打开全新的 `SmallPhone_v1006_CallMomentsBackgroundRepair/PhoneCompanionTest.xcodeproj`。
3. 选择 `PhoneCompanionTest` Scheme，检查签名、Bundle ID、App Group、推送与后台能力；执行 `Product → Clean Build Folder` 后再编译安装。
4. 先做普通微信聊天，确认基础回复正常。
5. 打语音电话，确认角色有字幕、有声音且不显示连接超时；这一步必须真实 iPhone 验证。
6. 在角色朋友圈发送普通评论、短句和回复某条评论，确认角色真实回复到准确位置。若接口失败，只能出现重试，不能出现假回复。
7. 进入“设置 → 聊天与媒体 → 立即模拟后台主动消息”，选择角色并确认后，马上把小手机退到桌面。等待真实通知，再返回 App 查看服务器模型与 APNs 的真实结果提示。
8. “APNs 已被 Apple 接受”只证明 Apple 接受投递；若通知仍不可见，还要检查 iPhone 通知权限、专注模式、设备令牌与系统展示，不得把两者混为一谈。
