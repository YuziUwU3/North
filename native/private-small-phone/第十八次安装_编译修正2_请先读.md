# 小手机 v893 编译修正 2

版本仍为：网页核心 v893／私人 iOS 1.0.18 (18)／原生桥契约 11。

这次不要再覆盖旧 `XcodeProject`。压缩包内提供全新独立目录 `SmallPhone_v893_CompileFix2`，请直接打开其中的 `PhoneCompanionTest.xcodeproj`。这样可以明确排除旧 `CompanionSyncView.swift`、旧 Xcode 工程路径和嵌套覆盖造成的混编。

## 只做三步

1. 把整个压缩包解压到 Mac 的一个新位置，不要放进原来的 `XcodeProject` 文件夹。
2. 进入 `SmallPhone_v893_CompileFix2`，只打开这里的 `PhoneCompanionTest.xcodeproj`；在 Xcode 选择 `Product → Clean Build Folder`。
3. 选择 `PhoneCompanionTest` Scheme 和真实 iPhone 重新运行。新的工程中 `registerPushTokenIfAvailable` 不是 `fileprivate`，`ContentView` 已包含 `approvedWithDataAccess` 分支，通知扩展也已显式链接 `Intents` 与 `UserNotifications`。

如果仍出现 `Command Ld failed`，请点击它左侧箭头并拍到下一层包含 `Undefined symbols`、`duplicate symbols` 或 `framework not found` 的完整文字；顶层这一句话本身没有具体链接失败原因。

Supabase 的 003、004 迁移和 `phone-role-push` 部署要求不变。Windows 的结构与自动化检查不能代替 Mac 链接和真机运行结果。
