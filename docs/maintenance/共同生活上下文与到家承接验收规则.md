# 共同生活上下文与到家承接验收规则

更新时间：2026-08-10

## 功能边界

- 旧的线下约会仍是一次性会话；共同生活是同一角色的长期线下生活。
- 两者复用角色设定、角色所选模型路线、线上长期记忆、旧约会记忆与必要的最近上下文。
- 微信、一次性约会、共同生活的可见消息分别保存，不得为了互通而复制气泡、旁白或改变旧格式。
- 「约会中同步到线上 · 含共同生活」是唯一上下文互通开关。关闭后按平行独立世界处理。

## 时间与生活状态

- 模型每轮必须收到当前准确日期时间、共同生活开始时间及持续时长、当前状态开始时间及持续时长、最近回家时间。
- 角色可通过结构化状态标签自主选择在家、上班、回家路上或临时外出；界面只展示已经被系统解析并保存的状态。
- 「开门」只代表到门口；只有明确的「我到家了／进门了」或对应结构化状态，才可切回在家。
- 共同生活启用时，微信顶部生活标签和共同生活页必须读取同一份状态；关闭共同生活后不显示该标签。

## 到家承接

- 线上状态从非在家切换到在家时，必须排队生成一轮真正的共同生活回复。
- 成功标准是共同生活记录里新增至少一段角色旁白或动作和一段角色台词；只显示「回来了」横幅不算成功。
- 微信原句只作为隐藏承接背景，不得原样复制到共同生活可见记录。
- 生成失败时保留到家状态和待承接任务，允许重试；不得伪造硬编码角色台词。

## 位置与双方一起外出（v868）

- 生活阶段、是否处于同一面对面现场和具体位置必须分开保存；顶部状态、微信状态与共同生活输入权限读取同一份持久化状态。
- 真正移动到卧室、书房、客厅、厨房、阳台等地点后才更新位置。询问、建议、未来计划、想象、条件句和否定句不得仅凭地点关键词触发移动。
- 双方一起外出使用独立的 `together-away` 阶段，顶部明确显示“一起外出 · 地点”，并继续使用共同生活面对面输入，不得误切微信。
- 双方一起回家不生成“角色单独到家”横幅或重复进门承接。只有角色此前单独上班、外出或在回家路上，真正到家后才进入线上到线下承接队列。
- 一次性旧约会的第三人称旁白、普通台词、逐字显示与可见记录格式不因上述状态扩展而改变。

## 日期、星期与共用作息（v868）

- 共同生活每轮必须收到真实年月日、星期、时分以及昨天/今天/明天的星期关系；相对日期只能由真实时间戳计算，不允许模型猜测。
- 共同生活直接复用角色线上已有的 `c.sched`，并在共同生活顶部设置区提供同一份作息表入口；禁止另存第二份共同生活作息。
- 周一至周五按照用户设置的上午工作、午休、下午工作和下班时间执行；周六、周日默认休息，除非现场已经明确出现请假、调休或临时加班等例外。
- 作息到达上班时间后，角色必须先在面对面现场完成准备、告别和真实出门，再输出上班状态。程序不得仅凭钟点自动切成线上；确认不再同一空间后才显示微信入口。
- 共同生活页面顶部实时显示年月日、星期和时间，且不得挤压角色名或生活状态标签。

## 发布前强制验收

1. 角色模型路线：共同生活使用角色选择的主／备用路线，一次性约会的旧默认不被改变。
2. 上下文互通：开关开启时能读取微信和旧约会的相关背景；关闭时完全隔离。
3. 格式隔离：微信气泡、旧约会格式、共同生活旁白格式不互相污染。
4. 准确时间：跨日、离开时长、当前状态持续时长均来自时间戳计算。
5. 到家完整链路：微信明确到家 → 状态切换 → 共同生活新增真实回复 → 可继续当面对话。
6. 旧功能回归：一次性约会、防复读、逐字显示、手动回复模式全部通过。
7. 必须同时有自动化集成测试和正式代码链路的本地浏览器验证；静态预览、状态横幅或仅看测试总数都不能代替完整链路。

## 2026-08-10 事故复盘

曾错误地把半独立的共同生活界面描述成已经与微信、模型路线和旧约会记忆完整互通；又把状态横幅出现和单元测试通过当作完整功能成功。实际存在角色已在微信说到家、共同生活仍显示外出，以及「让TA回应」没有真实回复的问题。

根因是状态同步、提示词上下文、模型路由和实际消息生成分散实现，没有一条端到端的到家承接事务；验收只覆盖了静态状态和源码片段，没有验证可见的共同生活消息落库。以后不得在未完成上述七项验收前宣称功能已经接好或测试成功。
