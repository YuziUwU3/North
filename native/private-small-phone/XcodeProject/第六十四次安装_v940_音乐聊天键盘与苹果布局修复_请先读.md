# 第六十四次安装：v940 音乐聊天键盘与苹果布局修复

- 网页核心：v940
- 私人 iOS：1.0.64 (64)
- 原生桥契约：18
- 必须完整解压本次 ZIP，只从全新目录 `SmallPhone_v940_MusicKeyboardGlass` 打开 `PhoneCompanionTest.xcodeproj`，不要覆盖旧工程。

## 本次变化

1. 开启“苹果兼容适配”后，音乐聊天输入框使用与微信相同的 WebKit 自然键盘上推，不再叠加旧的聚焦固定定位和三次强制滚回，避免首次点击必须下滑、页面弹跳及收起键盘再次回弹。
2. 音乐页顶部标题和双人头像的位置、尺寸保持原样；只压缩头像下方唱片、歌名、歌词和控制区的纵向占位，让聊天输入栏在 iPhone 主屏幕系统底部区域上方完整可见。
3. 音乐聊天框改为完整包裹灰色输入区的透明玻璃胶囊；原粉色发送键改为带高光、折射和内阴影的白色玻璃按钮。
4. 安卓不会启用苹果紧凑布局和自然键盘分支，继续保留原来的播放器几何与键盘收尾逻辑。
5. v939 通话拒绝拦截、单次副模型兜底与 TTS 播放前过滤全部保留；系统提示不显示模型名称，缩短为一句并在 10 秒后自动消失。

## 编译与验收

1. 解压后打开 `PhoneCompanionTest.xcodeproj`，选择 `PhoneCompanionTest` Scheme 与真实 iPhone。
2. 先执行 `Product → Clean Build Folder`，再编译安装。
3. 设置页顶部必须显示“当前已加载：v940 · 音乐聊天键盘与苹果布局修复”和“私人安装包 1.0.64 (64)”。
4. 在设置里开启苹果兼容适配，进入音乐播放器确认头像未移动、底部聊天栏完整可见；第一次点击输入框应直接出现光标并随键盘自然上推，连续打开／收起三次不应上下弹跳。
5. 关闭苹果兼容适配复核原布局；再用安卓网页确认唱片、歌词、控制键和输入栏没有套用苹果紧凑规则。
6. Windows 自动测试和静态检查不能代替 Mac 编译、签名及真实 iPhone／Android 的键盘和触摸验收。

## 保留边界

- iPhone 主屏幕底部系统区域继续保持 v934 原处理，本次没有尝试移除、改色或拉长该系统区域。
- v938 第二页人物和三拍立得组件、v937 音乐完整性／音乐库来电铃声／安卓视频诊断／iOS 26 微信光标修复保持原样。
- 电话、视频、字幕、语音识别、屏幕共享与角色消息业务没有改动。
