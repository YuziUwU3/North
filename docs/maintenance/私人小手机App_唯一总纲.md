# 私人「小手机」App 唯一总纲

状态：已确认，2026-08-11 起生效。

本文是公开 North、私人「小手机」和网页版后续工作的最高级产品与技术约束。旧文档中“私人版名称未定”“继续用公开 North 控制本人设备”等内容全部失效；发生冲突时以本文为准。

## 1. 最终形态

- 公开版继续叫 **North**，供其他用户使用；当前审核中的版本保持不动。
- 私人版固定叫 **小手机**，只安装到本人设备；沿用现有猫咪图标，只修改 App 名称。
- 私人版是完整、独立的真实 iOS App，不是网页链接、PWA 或只打开远程网址的壳。
- 网页版继续保留，供安卓和浏览器使用。
- 三个入口共用后端、数据结构和主要业务代码。网页业务资源只有一份源码；私人 iOS App 在构建时把同一份资源打包进安装包，不复制维护第二套业务逻辑。
- 私人 App 的界面和普通功能本地可打开；AI、云同步、跨设备数据等需要联网的能力仍按功能需要联网。

## 2. 控制权隔离

- 公开 North 和私人「小手机」绝不能同时控制同一台真实 iPhone。
- 本人设备最终只由私人「小手机」持有 Family Controls、Device Activity 和 Managed Settings 控制权。
- 私人版启用前必须完成控制权迁移：停止公开 North 对本人设备的控制、废止其服务端控制凭据、确认私人版获得授权后再启用自动控制。
- 后端必须保存明确的 `controllerKind`、控制器实例 ID、租约版本和更新时间；旧控制器的命令一律拒绝，不能只靠界面隐藏来实现隔离。
- 同一条命令必须有稳定幂等键；重试只补做未完成步骤，不能重复执行。

## 3. 不可违背的验收标准

### 永久锁定

- 锁定不能因刷新、同步、重连、后台唤醒、快照更新、跨日、重新打开 App 或限额重算而自行解除。
- 仅两种操作可以解锁：角色明确发出解锁命令且收到真实 iPhone 执行回执；本人点击手动解锁。
- 达到每日限额可以自动锁定；跨日只重算用量，不能自动清除锁定。
- 收到真实执行回执前，不得显示“锁定成功”或“解锁成功”。

### 使用时间

- 昨天和今天严格分开；总屏幕时间、逐 App 时间和限额进度必须使用同一使用日数据。
- 快照同时保存使用日、采集时间、上传时间、时区、递增序号和来源设备。
- 旧快照不能覆盖新快照；页面刷新不能把已锁状态恢复成旧的未锁状态。

### 同步与回执

- 前台立即同步，后台被系统唤醒后自动同步，失败自动重试。
- 页面明确区分“命令已发送”“设备已收到”“设备已执行”；失败也必须显示真实失败阶段。
- 快照较旧只作提示，不能阻止发送锁定命令。
- 网络中断不能改写本地锁定账本，也不能把未知状态当作解锁。

## 4. 必须保留的旧功能

- 线上与线下共同生活只能有一边查手机和发消息。
- 线上线下共享查岗去重；每日必查总屏幕时间、逐 App 时间、睡眠、步数。
- 线下角色可口头锁定、解锁、修改限额，并等待真实设备回执。
- 普通共同生活对话继续使用用户设置的主模型；副模型只重试失败的当前一轮，下一轮恢复主模型；切换时显示三秒提示。
- “旁白”按钮只切换下方输入框模式，不弹中央输入框。
- 已稳定的跨渠道真实时间轴、说话人身份、上一句锚点和各独立 App 安全区不得回退。

## 5. 私人 iOS App 技术边界

- 主 App：SwiftUI 容器、本地打包的网页核心、原生桥、账号恢复、Keychain、持久缓存和同步状态。
- 原生能力：Family Controls 授权与选择、Device Activity Monitor/Report、Managed Settings Shield、后台通知与命令执行。
- 网页核心：现有聊天、共同生活、各内置 App 和设置；通过版本化原生桥请求真实设备能力。
- 数据原则：本地锁定账本优先保证安全，云端是跨设备主数据；两者合并时只能保留或加强锁定，不能由旧云快照解除锁定。
- 2026-08-11 已从用户提供的 `AppleProjects.zip` 取得真实 Mac 工程，确认五个 Target、Team、Bundle ID、App Group、entitlements 和现有 MapKit 实现。私人副本沿用已经签名可用的标识，只修改显示名称；审核工程本身保持不动。
- 崩溃日志中的 MapKit/VectorKit 后台看门狗已命中真实 `ContentView.swift`：授权定位后，SwiftUI `Map` 在 scene 进入后台时仍常驻。私人副本在 `.inactive` 阶段即移除地图视图，定位采集继续独立运行；必须通过真机前后台回归后才算修复完成。
- v881 的旧 8 秒竞速使用结构化 `withTaskGroup`，退出作用域仍会等待不响应取消的 DeviceActivity 子任务，不能真正解除“同步中”。私人副本改用不等待输家的 `AsyncStream` 竞速，并在晚到任务写状态前检查取消，禁止超时结果覆盖新快照。
- 2026-08-11 第一次真机安装已成功覆盖同 Bundle ID 的旧伴生包，原生屏幕时间页面和既有本地数据仍在；私人主界面白屏的 Xcode 真实日志为 `url is not inside resource directory url`、`outside the sandbox`。根因是 WKWebView 主文件 URL 与授予读取权限的目录没有按同一标准化路径生成。修复后构建脚本从共享 `小手机.html` 额外生成只作入口的 `PhoneWeb.bundle/index.html`，原生端从该入口推导唯一父目录并传给 `allowingReadAccessTo`；加载失败必须显示诊断页，禁止再用无提示白屏掩盖资源错误。
- 用户现有 `North备份_2026-08-10.json` 已只读验证：JSON 完整，约 4.5 MB、55 个顶层数据块。正式导入必须等私人主页面成功加载后再执行，导入前保留原文件并校验，不能拿空白新容器覆盖此备份。
- 私人 1.0.5 (5) 候选把话筒转字幕接入 iOS Speech/AVAudioEngine 原生桥，按原生键盘 frame 与 visualViewport 的差值修复通话和音乐输入栏，清除共享推送造成的固定假角标，并把真实设备管理入口限制在设置页。公开 North 仍保持 v881；这些候选能力必须经过真机授权、转写、键盘和角标验收后才能称为完成。
- v884／私人 1.0.8 的真机结果证明，单纯把输入框固定到底部、在角色语音前后 pause/resume 仍不足以解决问题。WKWebView 弹出键盘时会自动滚动最外层 UIScrollView，CSS 无法阻止整个通话页面上下跳；WebKit 语音播放完成回调又可能早于 AVAudioSession 真正释放，旧引擎即使返回“恢复成功”也可能已经失去输入。
- v885／私人 1.0.9 改用原生层处理这两个根因：仅在电话输入框聚焦期间锁定 WKWebView 外层滚动位置，电话输入改为微信式“点开输入—发送后收起—手动收起”的两态编辑器；角色语音结束后等待音频路由释放，再无条件清理并新建 AVAudioEngine、识别请求和任务。网页/PWA 已由用户确认恢复，本轮不再改其布局和话筒行为。
- 强制规则：私人 App 的键盘跳动不得再靠反复修改 CSS bottom 数值处理；角色播放后的连续录音不得仅调用 resume 或依赖 JS active 状态。必须分别以原生滚动锁和完整音频栈重建处理，并在真机连续完成至少三轮“用户说—角色说—用户再说”后才可判定通过。

## 6. 当前实施顺序

### 2026-08-11 v886／私人 1.0.10 通话键盘根因修正

- 真机复验结论：v885 的原生语音完整重建已经解决连续语音失效，必须保留；但 v885 的原生固定输入框、`contentOffset` 观察与滚动锁并没有解决键盘跳动，反而与 WKWebView 自带的键盘页面位移形成两套布局权威。
- 已确认对照基准：网页版／PWA 在同一通话页上表现正常，键盘出现时由浏览器把整个页面平滑上移；输入框位于挂断按钮上方，收起键盘后整体自然回位。
- v886 删除私人 App 独有的电话输入框分支、两态固定编辑器、焦点桥消息、`contentOffset` KVO 与强制滚动回写；原生 App 直接复用网页版同一份 `.callinput` 和 `.callbtns` 结构、位置及系统键盘行为。
- 强制规则：电话页只能有一个键盘布局权威。不得再为 `north-native-app` 单独覆盖 `.callinput`／`.callbtns`，不得监听并回写 WKWebView 外层滚动位置，不得用另一套原生两态输入框模拟网页输入框。
- 不可回退：原生语音在角色音频结束后延迟释放并完整重建 AVAudioEngine、识别请求和任务的修复继续保留；布局修复不得改回旧的 `resume` 假恢复。
- 验收要求：自动化 447/447 通过只说明回归契约成立；仍需真机连续多次打开键盘、发送、收起，确认整个页面与网页版同样平滑移动、没有上下闪跳，且挂断按钮始终在输入框下方，再连续完成至少三轮“用户说—角色说—用户再说”。

### 2026-08-11 私人 1.0.11 原生外框固定修正

- 真机否定结果：私人 1.0.10 虽删除了网页层第二套输入框与滚动锁，但开合键盘仍会先下拉再上弹，说明 v886 对根因只处理了一半。
- 新根因：`SmallPhonePrivateRootView` 只忽略 `.container` 底部安全区，没有忽略 `.keyboard` 安全区。键盘出现时 SwiftUI 会先缩小整个 `UIViewRepresentable`／WKWebView 外框，随后 WebKit 又为聚焦输入框执行自己的可见性处理，形成两次方向相反的页面动画。
- 修正：私人 1.0.11 在原生根视图增加 `.ignoresSafeArea(.keyboard, edges: .bottom)`，固定 WKWebView 外框尺寸；网页核心仍为 v886，不再改网页版 CSS，也不回退已经修好的原生连续语音重建。
- 强制规则：以后遇到原生键盘导致整页跳动，必须先检查 SwiftUI 根容器是否响应键盘安全区；不得先改网页 `bottom`、不得恢复 `contentOffset` KVO，也不得把已正常的网页版一起改坏。

### 2026-08-11 v887／私人 1.0.12 手机号账号与云恢复

- 手机号入口只在私人「小手机」App 的「设置 → 授权·数据」出现；公开 North 与网页版不显示、不持有该登录态。
- 验证码通过 Supabase Auth Phone OTP；访问令牌与刷新令牌只存 iOS Keychain，不交给网页 JavaScript。
- 云备份表按 `auth.uid()` 开启 RLS，一名用户只能读写自己的备份；上传同时保存数据采集时间、上传时间、版本、大小和校验值，旧采集时间禁止覆盖新备份。
- 首次绑定时：云端为空才自动上传当前本机；云端已有数据则必须由用户明确选择保留本机或恢复云端，绝不静默覆盖已经导入的数据。
- 当前上线前置条件：Supabase 后台启用 Phone Provider 并配置短信服务，然后执行 `supabase/migrations/202608110001_private_phone_accounts.sql`。未完成前，App 必须明确显示账号服务不可用，不能伪装成绑定成功。

### 2026-08-11 v888／私人 1.0.13 中国大陆手机号密码登录

- 用户确认最终目标不变：私人 App 仍以手机号作为可见账号，删除或重装后输入手机号和密码恢复云端数据；底层实现不要求必须发送短信验证码。
- v887 的 Phone OTP 方案不再作为当前实施方向。Supabase 托管 Phone Auth 必须另配短信供应商，而中国大陆私人号码没有现成供应商凭据，继续依赖 Twilio 会让登录入口在真实环境不可用。不得为了保持“验证码”形式而让用户购买或配置未经真机验证的境外短信链路。
- v888 改为 Supabase Email/Password 登录，但 App 界面不暴露邮箱：原生桥先把中国大陆号码规范化为 `+86`，再确定性映射为 `smallphone.86手机号@example.com`。该内部邮箱只作 Auth 标识，公开 North 与网页版均不得显示或使用这套私人登录态。
- 密码只随当前登录请求发给 Supabase Auth，不写入网页状态、本地文件、日志、UserDefaults 或 Keychain；Keychain 只保存访问令牌、刷新令牌、到期时间、用户 ID 和用于遮罩显示的手机号。
- Phone Provider、Twilio 和短信服务保持关闭。首次启用只需执行 `supabase/migrations/202608110001_private_phone_accounts.sql`，并由本人在 Authentication 中手动创建一名已确认的内部邮箱用户；禁止开放公共自助注册。
- 云备份表、`auth.uid()` RLS、采集时间优先、旧备份不得覆盖新备份、首次登录必须明确选择保留本机或恢复云端等安全规则全部不变。

## 7. 完成定义

只有当私人「小手机」可在真机独立安装、本人设备只受它控制、所有关键状态均有真实设备回执，并通过第 6 节的真机测试后，才可称为“私人 App 完成”。仅有源码骨架、网页壳或模拟器通过都不算完成。
