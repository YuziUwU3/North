# 第二十次安装：真实全量读取与后台记忆修复

本次必须从压缩包内全新的 `SmallPhone_v895_FullReadMemoryPushFix` 目录打开 `PhoneCompanionTest.xcodeproj`，不要再覆盖到第十九次或更早的工程。版本是私人 iOS 1.0.20 (20)，内置网页核心 v895，桥契约 11。

## 这次真正修了什么

- 电量和位置原本成功，是因为它们分别走 `UIDevice` 与 CoreLocation，不依赖屏幕时间或健康权限。
- 健康数据此前网页按钮虽然开启，原生 HealthKit 同步并未开启；现在角色明确读取时会真正请求并刷新步数、睡眠、心率、心电和 HRV。
- 中国真机无法使用只向欧盟正式用户开放的 Screen Time 直接数据 API；现在普通 Family Controls 授权会改走工程里已有的 Report 扩展，把当日总时长与逐 App 数据回传给主 App。
- 读取全部不再只回答一个位置或电量，而会逐项报告九类数据的值或失败原因。
- 后台主动消息的远端 RPC 和调度迁移已实际部署；旧版 App 使用的参数名也兼容。
- 彻底清空会同时清理本地大聊天归档、共同生活上下文、服务端上下文和待发送旧消息。

## Mac 安装顺序

1. 解压到一个全新目录，不要与旧目录合并。
2. 用 Xcode 打开 `SmallPhone_v895_FullReadMemoryPushFix/XcodeProject/PhoneCompanionTest.xcodeproj`。
3. 选择 `PhoneCompanionTest` Scheme 和真实 iPhone，执行一次 Clean Build Folder 后运行。
4. 首次读取全部时按系统提示允许健康、位置和 Family Controls；健康 App 中也要允许需要的类别。
5. 在 App 内执行一次“读取全部”，确认顶部横幅逐项变化，最终回复逐项列出九类结果。

## 仍必须在真机确认

- Xcode 五个 Target 均能编译签名。
- Report 扩展能回传屏幕总时长和逐 App 数据。
- HealthKit 首次授权后能读取已有真实记录；没有心电记录时应明确显示无记录，不得编造。
- 前台、后台和强退后的主动消息／来电通知，以及通知头像。
- 手动解锁受控 App 后角色能收到真实事件并联系。
